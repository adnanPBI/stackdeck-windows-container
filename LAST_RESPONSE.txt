  ## How VM Creation Works in the Package — Precise Answer

  ### 1. Does the NSIS/MSI Package Create the VM Automatically?

  ❌ NO. The installer does NOT create the VM.

  Here's exactly what happens at each stage:

    ┌─────────────────────────────────────────────────────────────────┐
    │  NSIS / MSI Installer  (what it DOES do)                        │
    │                                                                  │
    │  ✅ Copies  stackdeck-cli.exe + stackdeck-hive.exe                │
    │  ✅ Installs Tauri GUI (StackDeck.exe)                           │
    │  ✅ Creates Start Menu shortcut                                  │
    │  ✅ Sets up uninstaller                                          │
    │  ✅ Optionally installs WebView2 bootstrapper                    │
    │                                                                  │
    │  ❌ Does NOT: create Hyper-V VM                                  │
    │  ❌ Does NOT: download cloud image                               │
    │  ❌ Does NOT: run any PowerShell scripts                         │
    │  ❌ Does NOT: check for Hyper-V feature                          │
    │  ❌ Does NOT: run any first-run wizard                           │
    └─────────────────────────────────────────────────────────────────┘

  The user must run the following manually after install (from an Admin PowerShell):

    # Step 1 — Configure VM parameters
    stackdeck hyperv configure --vm-name stackdeck-linux --disk-gb 20 --memory-mb 4096

    # Step 2 — Generate SSH key
    stackdeck hyperv ensure-key

    # Step 3 — Download image + create VM + bootstrap (single command)
    stackdeck hyperv init --url https://cloud-images.ubuntu.com/jammy/current/jammy-server-cloudimg-amd64.img --sha256
  <sha256>

    # Step 4 — Verify
    stackdeck hyperv health

  Or use the all-in-one deployment script:

    .\scripts\windows\Invoke-StackDeckLocalDeploy.ps1 -Phase All -Sha256 <sha256>

  ### 2. Fixed Size or Dynamic Size?

  The VHDX disk is DYNAMIC, but with a configurable fixed ceiling.

  Here's exactly what the code does (lib.rs):

    # What Hyper-V creates:
    New-VHD -Path $disk -Dynamic -SizeBytes {disk_gb}GB

   Property                                   │ Current Behaviour
  ────────────────────────────────────────────┼───────────────────────────────────────────────────────────────────────
   VHDX type                                  │ Dynamic (sparse on disk, grows on write)
   Logical ceiling                            │  vm_disk_gb  from config — hardcoded default: 10 GB
   Floor                                      │ Clamped to  max(10)  — will never go below 10 GB regardless of config
   Based on free space?                       │ ❌ NO — no free-space detection for disk sizing
   Configurable by user                       │ ✅ YES —  stackdeck hyperv configure --disk-gb 40

  Memory is different — it DOES auto-adapt to available RAM:

    # From the code (vm_start method):
    $freeMb = [math]::Floor($os.FreePhysicalMemory / 1024)
    $availableMb = $freeMb - 1024          # keeps 1GB for Windows
    $targetMb = if ($availableMb -lt $configuredMb) { $availableMb } else { $configuredMb }
    if ($targetMb -lt 1024) { $targetMb = 1024 }   # minimum 1GB
    Set-VMMemory -DynamicMemoryEnabled $true -StartupBytes ($targetMb * 1MB) -MaximumBytes ($configuredMb * 1MB)

  So:

  • Disk: Dynamic VHDX, size ceiling is operator-configured (default 10 GB), NOT auto-detected from free space
  • Memory: Auto-adapts on VM start — uses  min(freeRAM - 1GB, configuredMax) , minimum 1 GB
